# Noor (نور) — Product & Technical Specification v2

A Quran-first web app: a beautiful digital Mushaf, a reliable daily Adhkar companion, a personal reading tracker, a memorization assistant, and prayer utilities. Arabic-first, mobile-first, calm, and distraction-free.

---

## 0. How to work with this spec (rules for the coding agent)

5. **Communicate with me in Arabic.** Code, comments, commit messages and docs in English.

7. **Content integrity rules in §2 override everything else in this document.**

## 1. Product principles

- The Quran is the most important part of the app. When the Mushaf is open there is almost nothing else on screen.
- Calm and respectful: no ads, no popups, no banners between ayahs, no aggressive notifications, no manipulative gamification.
- Mobile is a first-class platform, not a shrunken desktop.
- Reading the Quran never requires an account.
- Public Quran content and private user data are strictly separated.

## 2. Content integrity (non-negotiable)

1. **Never type religious text from memory.** No Quran, Hadith, Adhkar, translation or Tafsir text may be written by hand or generated by an AI. All of it must be imported by a script from a named source file or URL.
2. **Provenance.** Raw source files are committed under `data/sources/`. `data/sources/SOURCES.lock.json` records for each file: source name, URL, download date, download options used, license or terms (quoted), and SHA-256.
3. **If no acceptable source is available, leave the section empty** and tell me. Do not fill gaps with "best-effort" text.
4. **No transformation of Quran text.** In particular:
   - No Unicode normalization (`String.prototype.normalize`, NFC/NFKC) anywhere in the Quran data path. It can reorder or change combining marks.
   - No regex cleanup, no character replacement, no trimming of characters inside ayah text, and no HTML-escaping that changes the stored string.
   - The only allowed derived text is the **search index** (§7.8). It is built from the separate "simple/clean" source text, is never displayed as Quran, and lives in its own field.
5. **Basmala.** Some distributions prefix the Basmala to ayah 1 of surahs 2–114. Prefer a source option that excludes it. If a script has to remove it, it must:
   - match the exact Basmala string of ayah 1:1, and fail otherwise;
   - be covered by a test;
   - be documented in `docs/SOURCES.md`.

   Display rule: in Al-Fatihah the Basmala is ayah 1. In surahs 2–114 (except At-Tawbah) it is shown as a separate, unnumbered header line. At-Tawbah has no Basmala.
6. **Automated integrity tests** (CI-blocking):
   - 114 surahs and 6,236 ayahs; the ayah count of every surah matches the metadata.
   - Every generated ayah string equals the source string, code point for code point. A SHA-256 over the canonical concatenation matches the value recorded at import.
   - **Rendering test:** Playwright reads the DOM `textContent` of rendered ayah text, excluding ayah-number elements, for sample surahs (1, 2, 9, 18, 36, 112–114). It must equal the source text exactly. This catches UI formatting that silently changes text.
7. **Adhkar.** Every dhikr must have a reference (book + number). Store a grading if the source provides one. A virtue (fadl) text is shown only with its own reference.
8. **Tafsir and translations** are always shown with their source name and author or translator. Never present AI-written explanations as tafsir.
9. **Uncertain dates** (Ramadan, Eids, etc.) are labelled as expected dates that depend on moon sighting.

## 4. Architecture & stack

- **Framework:** Next.js (latest stable, App Router), TypeScript in strict mode, React Server Components where useful.
- **Styling:** Tailwind CSS with design tokens as CSS variables (themes in §6).
- **i18n:** next-intl. Arabic is the default and RTL; English is LTR. All UI strings live in `messages/ar.json` and `messages/en.json`.
- **Database:** PostgreSQL (Neon in production; Neon dev branch or local Postgres in development) with Prisma. **Holds user data only.**
- **Auth:** Better Auth (email + password, password reset, optional email verification) with the Prisma adapter. Email via Resend.
- **Client storage:** IndexedDB via Dexie (local-first store); `localStorage` only for tiny boot-time preferences (theme, locale) to avoid a flash.
- **PWA:** Serwist service worker.
- **Testing:** Vitest (unit), Playwright (e2e, visual and rendering checks), axe-core (accessibility).
- **Deployment:** Vercel + Neon. A Dockerfile is a nice-to-have, not required.
- **Analytics:** none in v1.

### Key architectural decision: Quran content is static, not in Postgres
The Quran text, metadata, translations and tafsir are immutable datasets. An import script generates versioned JSON chunks into `content/`. These are committed to Git, so every content change is a reviewable diff, and served statically or through SSG from the CDN.

- No database round-trip to read the Quran.
- Trivially cacheable offline.
- Easy integrity verification.

Content is chunked so that opening one surah never loads the whole Quran:
- `content/quran/meta.json`: surahs, juz, hizb, quarters, pages, sajdahs.
- `content/quran/surah/{1..114}.json`: ayahs with page/juz/hizb/quarter per ayah.
- `content/translations/{id}/surah/{n}.json` and `content/tafsir/{id}/surah/{n}.json`: loaded lazily.
- `content/search/index.json`: normalized search text with ayah keys (§7.8).

### Folder structure (proposal)
```
app/[locale]/...        routes (home, quran, mushaf, adhkar, tasbih, prayer, qibla, calendar, saved, stats, settings, auth)
features/<name>/        feature modules (components, hooks, logic)
components/ui/          shared primitives
lib/                    quran data access, arabic normalization, storage, sync, i18n, audio
content/                generated static content (committed)
data/sources/           raw source files + SOURCES.lock.json
scripts/                import-quran.ts, import-adhkar.ts, import-translation.ts, verify-content.ts
messages/               ar.json, en.json
prisma/                 schema + migrations
tests/                  unit/, e2e/
docs/                   SPEC.md, DECISIONS.md, SOURCES.md
```

## 5. User data & sync

### Local-first model
- Every user record is created in IndexedDB first. The app is fully usable as a guest.
- Records have a client-generated UUID, `updatedAt`, and `deletedAt` (tombstone).
- On sign-up or login, local guest data is uploaded and merged into the account.
- Sync works through `POST /api/sync` with `{ cursor, changes[] }` and returns `{ changes[], cursor }`. It runs on load, on reconnect, after edits (debounced), and on visibility change.
- **Conflict policy:** last-write-wins per record by `updatedAt`. Daily activity merges by union (pages read) and max (seconds).
- The storage layer is built in Phase 4 with this shape, so adding sync in Phase 9 means plugging in a transport, not rewriting features.

### Entities (Postgres / Prisma, all scoped by `userId`)
- Better Auth tables (`User`, `Session`, `Account`, `Verification`)
- `UserPreferences`: JSON blob (reading settings, theme, locale, numeral style, prayer method), `updatedAt`
- `ReadingPosition`: surah, ayah, page, mode
- `ReadingDay`: date, pagesRead (int array of page numbers), secondsRead. Unique on (userId, date).
- `SavedItem`: type (`AYAH` | `PAGE` | `SURAH` | `DHIKR` | `TAFSIR`), ref (e.g. `2:255`), collectionId?, note?
- `Collection`: name, order
- `Note`: targetType, targetRef, body. Private, never public.
- `MemorizationItem`: surah, ayah, status, ease, intervalDays, dueAt, lastReviewedAt
- `Goal`: unit (`PAGES`), amount, activeFrom
- `AdhkarDay`: date, categoryId, counts JSON, completed
- `TasbihSession`: phrase, count, target, startedAt, endedAt

**Location privacy:** prayer location stays on the device by default. Syncing it is an explicit opt-in.

## 6. Design & UX

- Original, premium, calm Islamic design. Draw inspiration from modern Quran apps, Apple's design principles and traditional typography, but copy nothing.
- **Themes:** Light, Dark, and Sepia ("reading" background), plus optional pure black for OLED.
- **Avoid:** heavy gradients, decoration, huge cards, colorful noise, distracting animation.
- Subtle transitions only; all of them respect `prefers-reduced-motion`.
- **Mobile:** bottom navigation, 44px minimum touch targets, safe-area insets, controls within thumb reach.
- **Reader chrome:** tap the page to toggle it. Full-screen reading; optional Screen Wake Lock.
- **RTL details:** in Mushaf mode, swiping right goes to the next page in Arabic. Icons such as arrows mirror correctly.
- **Numerals:** setting for Arabic-Indic (١٢٣) or Western (123) digits.

## 7. Features

### 7.1 Home
- **Continue Reading** card: surah name, ayah, page. One tap goes to the exact position.
- **Today's Adhkar:** Morning, Evening, After Prayer, Before Sleep, each showing today's completion state. If prayer times are configured, Morning is gently highlighted before Dhuhr and Evening after Asr.
- **Quick access:** Quran, Adhkar, Search, Saved, Last read, Listen.
- **Daily progress:** pages read today against the goal, shown as a calm progress bar.

### 7.2 Surah list
- Each surah shows: number, Arabic name, English name, ayah count, Meccan/Medinan.
- Instant filter with normalized Arabic and English matching (e.g. "الكهف", "كهف", "kahf", "18").
- Tabs or segments: Surah · Juz · Hizb · Page.

### 7.3 Quran reader
Two modes; the user can switch at any time and the position is preserved.

- **Reading mode:** continuous text optimized for mobile. Translation is optionally shown under each ayah.
- **Mushaf mode:** one Madani page at a time (604 pages), using the page boundaries from the metadata, with a surah header frame and minimal page furniture. Be honest in the UI and docs: "page boundaries follow the Madani Mushaf; line layout is approximate." Line-exact layout (QCF per-page fonts) is a later phase.

Navigation: next/previous surah, page, ayah; jump to Juz, Hizb, quarter, page or surah:ayah; continue from the last position.

Always available but unobtrusive: surah name and number, juz, hizb/quarter, page number, ayah numbers (end-of-ayah marker), and sajdah markers.

### 7.4 Reading settings (saved automatically)
- Quran font (from the approved list) and font size (`A− 32px A+`)
- Line height and content width
- Theme and background
- Translation on/off and which translation
- Numeral style
- Tajweed colors: only if a properly licensed tajweed-annotated source is found; otherwise hidden.

### 7.5 Ayah actions
Tapping an ayah opens a small popover (desktop) or bottom sheet (mobile) with: Copy (with reference), Share (Web Share API with fallback), Save, Note, Play from here, Translation, Tafsir. No clutter. It is reachable by keyboard.

### 7.6 Saved items & notes (bookmarks and favorites merged)
- One "Saved" concept with types: ayah, page, surah, dhikr, tafsir.
- Optional collections (e.g. "Important", "To memorize") and an optional personal note per item.
- Notes can also attach to an ayah or dhikr without saving it.
- The Saved page has filters by type and collection, plus search.

### 7.7 Reading position & activity
- Position = the topmost visible ayah, saved with a debounce (~1s) locally and synced when signed in.
- **Page read:** a Madani page counts as read when it has been on screen for a cumulative ≥ 15s (Mushaf mode) or ≥ 50% of its ayahs have been visible for ≥ 15s (Reading mode). Constants are configurable. Counted once per day.
- **Reading time:** counts only while the tab is visible and the user was active in the last 60s, or while audio is playing.

### 7.8 Search & command palette
- **Quran search:** query and index are both normalized. Normalization removes tashkeel and tatweel, and unifies أ إ آ ٱ → ا, ة → ه, ى → ي, ؤ → و, ئ → ي. Do not convert ه → ة.
- **Query modes:** exact phrase, partial words, and all-words. Filters by surah and juz.
- **Results:** surah, ayah number, the Uthmani text with the match highlighted (map index positions back to words), and a link that opens the ayah.
- **Implementation:** the search index (≈1–2 MB) is loaded once in a Web Worker and queried in memory. This also works offline after the first load. Translation search is optional and per-translation.
- **Command palette (Ctrl/Cmd + K):** surahs, ayah references (`2:255`, `البقرة 255`), pages, juz, adhkar categories, saved items and notes, settings.
- Tafsir full-text search is out of scope for v1.

### 7.9 Translations
A translation registry (`content/translations/registry.json`) holds id, language, translator, source, license and direction. Adding one means running `scripts/import-translation.ts` with a new source file; no component changes. The translator and source are always visible.

### 7.10 Tafsir
Opens from the ayah menu in a sheet or side panel. A source selector uses the same registry pattern as translations. The source name and author are always shown.

### 7.11 Audio
- **Playback:** per-ayah playback from the approved source. A whole surah plays by sequencing ayah files, preloading the next ayah.
- **Controls:** play/pause, next/previous ayah, repeat ayah ×N, repeat range or surah, speed 0.75–2×, reciter selector.
- **Now Playing:** surah, ayah and reciter. The current ayah is highlighted in the reader, with optional auto-scroll.
- **Persistent mini player** in the root layout so it survives navigation, positioned above the bottom navigation on mobile.
- **Media Session API:** lock-screen controls and metadata.
- **Offline audio:** v1 offers no offline download unless the source's terms explicitly allow it.

### 7.12 Memorization
- Select a surah and an ayah range.
- **Practice modes:** hide all text, first letter of each word, or hide every other word.
  - This is a clearly labelled display mask; the stored text is untouched.
  - Word tokens that contain only pause or annotation marks are not words.
  - A "first letter" means the first grapheme cluster (the letter with its marks).
- **Reveal:** tap to reveal a word, or "Show answer" for the whole ayah.
- **Self-assessment:** "Didn't know" / "Hesitant" / "Knew it". Lightweight spaced repetition (SM-2-style) schedules the next review, and a "Due today" list is shown.
- **Progress:** "Al-Mulk — memorized 12/30 ayahs (40%)". An ayah counts as memorized after 3 successful reviews with an interval of at least 7 days.

### 7.13 Goals, consistency & statistics
- **Daily goal:** in pages (presets 2 / 5 / 10 / 20; "1 Juz ≈ 20 pages").
- **Progress views:** today, this week, this month.
- **Consistency:** show "days read this week/month" and the current streak. Never use loss-framed messages ("you'll lose your streak!"). The streak display can be hidden.
- **Statistics:** pages read, surahs completed, items saved, reading time, adhkar sessions completed, a weekly activity chart, and a simple calendar heatmap. For self-improvement only; there are no leaderboards.

### 7.14 Adhkar
- **Categories:** Morning, Evening, After Prayer, Before Sleep, Upon Waking, Entering the Mosque, Leaving the Mosque, Before Eating, After Eating, Travel, Distress & Anxiety, General Dhikr.
- **Each dhikr card shows:** the Arabic text, translation (if licensed), reference, grading if available, and the counter.
- **Counter:** a large tap target; the whole card is tappable. It shows `1 / 3`, with −1 and reset. A subtle completion state appears when the target is reached, with optional auto-advance to the next dhikr.
- **Persistence:** counts are saved on every tap, survive reload, and reset at local midnight.
- Completion of a category is recorded in `AdhkarDay`.

### 7.15 Tasbih
- **Phrases:** presets (سبحان الله، الحمد لله، الله أكبر، لا إله إلا الله) or a custom phrase.
- **Target:** 33, 99, 100 or custom, with a progress ring or bar.
- **Controls:** +1 (huge target), −1, and reset with confirmation.
- **Feedback:** vibration where supported (not on iOS Safari; hide the toggle there). Optional sound, off by default.
- Session history (last 30 sessions). The count persists across reloads.
- Uses the same counter component as the Adhkar cards.

### 7.16 Prayer times
- **Location:** search the bundled city list, or use the browser location only after the user explicitly taps "Use my location". Never ask for location on page load.
- **Calculation:** method defaults by country (e.g. Umm al-Qura for Saudi Arabia), with Asr madhab (Shafi'i/Hanafi), a high-latitude rule and manual minute adjustments.
- **Display:** Fajr, Sunrise, Dhuhr, Asr, Maghrib and Isha in the city's time zone, plus a "Next prayer" card with a live countdown.

### 7.17 Qibla
- **Bearing:** from adhan-js `Qibla()`, always shown numerically relative to true north, with the distance to Makkah.
- **Live compass:**
  - iOS uses `webkitCompassHeading` after `DeviceOrientationEvent.requestPermission()` is triggered by a user tap.
  - Android uses `deviceorientationabsolute`.
- **Declination:** document whether each heading source is true or magnetic north. Correct with a declination model if needed, or state the limitation clearly.
- **Accuracy:** show a calibration hint and a clear accuracy disclaimer.
- **Fallback:** without sensors, show a static dial with the bearing and instructions.

### 7.18 Hijri calendar
- Today's Hijri and Gregorian dates.
- A month grid showing both calendars.
- A user adjustment of ±2 days.
- An important-dates list (1 Muharram, Ashura, Ramadan, Eid al-Fitr, Day of Arafah, Eid al-Adha), each labelled "expected — depends on moon sighting".

### 7.19 Accounts
- **Optional accounts:** register, login, logout, password reset (email), and optional email verification.
- **Synced:** saved items, notes, reading position and activity, goals, preferences, adhkar progress, memorization and tasbih history.
- **Settings:** "Export my data" (JSON) and "Delete my account", which permanently deletes server data after confirmation.

### 7.20 Offline / PWA
- **Installable:** manifest, icons, and an Arabic name and short name.
- **Precached:** the app shell, fonts, `meta.json`, the surah list, adhkar data and the search index.
- **Runtime cache:** recently opened surah, translation and tafsir chunks use stale-while-revalidate.
- **"Download Quran text for offline":** an explicit button that fetches all 114 surah chunks and shows progress and size.
- **Honest UI:** settings show what is available offline. The offline banner reads: "لا يوجد اتصال بالإنترنت. المحفوظات والقراءة الأخيرة متاحة." / "No internet connection. Your saved items and recent reading are still available."
- Pending sync changes are queued and flushed on reconnect.

## 8. Localization
- Arabic is the default at `/`; English lives at `/en/...`.
- `dir` and `lang` are set per locale. Quran text is always `lang="ar" dir="rtl"`, even in the English UI.
- No hard-coded UI strings. Use ICU plurals: Arabic has six plural forms ("آية / آيتان / آيات").
- Dates and numbers are formatted with `Intl` according to the locale and numeral setting.

## 9. SEO & URLs
- **Canonical URLs:** `/quran/al-baqarah`, `/quran/al-baqarah/255`, `/mushaf/page/50`, `/juz/1`, `/adhkar/morning`, plus their English equivalents under `/en`.
- `/quran/2` and `/quran/2/255` redirect (308) to the slug URLs. Slugs come from a reviewed data file.
- **Rendering:** the 114 surah pages and the adhkar category pages are statically generated with the Arabic text server-rendered. Ayah pages are rendered on demand and cached (ISR).
- **Metadata:** per-page titles and descriptions, canonical URLs, hreflang ar/en, Open Graph (OG images per surah via `next/og`), `sitemap.xml` (surahs, juz, adhkar), `robots.txt`, and JSON-LD `BreadcrumbList` + `WebSite` with `SearchAction`.
- No thin or spam pages, and nothing private is ever indexed (`/saved`, `/stats`, `/settings` and auth pages get `noindex`).

## 10. Accessibility
- Semantic HTML, visible focus states, full keyboard navigation in the reader (arrow keys move by ayah, PageUp/PageDown by page), and focus traps in sheets and dialogs.
- Ayah numbers carry an `aria-label` such as "آية ٢٥٥".
- WCAG AA contrast in all themes, text scaling up to 200% without breaking layout, and `prefers-reduced-motion` respected.
- axe checks run in the e2e suite.

## 11. Performance budgets
- **Mobile Lighthouse:** Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO = 100.
- **Reader route:** JS ≤ 150 KB gzipped, excluding fonts and content.
- **LCP:** < 2.5 s on mid-range Android over 4G.
- **Fonts:** self-hosted woff2; subset the UI font; preload only the active Quran font.
- **Long surahs:** render progressively or virtualize (Al-Baqarah must scroll smoothly). Translations and tafsir load lazily.
- **Audio:** load on demand; preload only the next ayah.

## 12. Security & privacy
- Every API input is validated with Zod.
- Every query is scoped to the session `userId`.
- Better Auth defaults for password hashing and httpOnly secure cookies.
- CSRF protection, rate limiting on auth and sync endpoints, and security headers including a strict CSP.
- Secrets live only in environment variables, never in client bundles.
- No admin panel in v1. Religious content changes go through Git (reviewable diffs) and the import scripts.
- **Privacy:** no third-party trackers; location stays on the device by default; minimal personal data (email only). A privacy page explains all of this in plain language.

## 13. States
Every data view has a polished loading state (skeletons matching the final layout), an empty state, an error state with retry, and an offline state. There are no layout jumps when content arrives.

## 15. Testing
- **Unit (Vitest):**
  - Arabic normalization and search matching;
  - ayah reference parsing (`2:255`, `البقرة ٢٥٥`);
  - page/juz/hizb lookups;
  - SRS scheduling;
  - sync merge and conflict rules;
  - prayer settings mapping to adhan params (spot-check against an official published timetable; record the source in the test);
  - counters.
- **Content integrity (§2.6):** blocks CI.
- **E2E (Playwright)** at four viewports (1440×900, 820×1180, 390×844, 412×915), in Arabic and English, light and dark, running this user journey:
  1. Open the Quran, open a surah, and read several ayahs.
  2. Save an ayah with a note.
  3. Reload in a fresh context with the same storage, then use Continue Reading to land on the same ayah.
  4. Search for an ayah and open the result.
  5. Play audio (with the network mocked).
  6. Open Morning Adhkar and use the counter.
  7. Reload: the count persists.
  8. Set a city and check that prayer times render with a next-prayer countdown.
  9. Switch Arabic ↔ English and dark ↔ light.
  10. Go offline: a cached surah and saved items still work, and the offline banner shows.
- **Manual checklist** (for me, on real devices): compass, vibration, background audio, install-to-home-screen, and iOS storage behavior.
